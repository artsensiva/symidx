# Спецификация поведения symidx

Все реализации (`goose/`, `rust-idiomatic/`, `rust-expert/`) обязаны следовать этим правилам
байт-в-байт: эталон — `bench/ref.py`, проверка — `bench/run.sh` (сравнение sha256 вывода `find "" `).

## Обход
- Рекурсивно от `<dir>`; берутся только **обычные файлы** с именем, оканчивающимся на `.py`.
- Симлинки (на файлы и на каталоги) не открываются и не обходятся.
- Путь файла в индексе — относительно `<dir>`, разделитель `/`, без `./` в начале.

## Разбор строки
Файл читается как байты и режется по `\n` (номер строки начинается с 1). Для каждой строки:
1. Пропустить ведущие пробелы и табы (`0x20`, `0x09`).
2. Если дальше `async`, а за ним ≥1 пробел/таб — пропустить их тоже.
3. Ключевое слово: `def` → kind `def`, `class` → kind `class`; иначе строка не символ.
   После ключевого слова обязателен ≥1 пробел/таб; пропустить их.
4. Имя — максимальная последовательность байтов из `[A-Za-z0-9_]` или `>= 0x80`.
   Пустое имя → строка не символ.

Строки и комментарии не распознаются: `def x` внутри docstring тоже считается символом.
`async` без `def` после него (например, `async class`) — не символ.

## Хранение строк (обязательно для всех реализаций)
- **Имена символов интернируются**: в образе каждое уникальное имя хранится ровно один раз,
  запись символа ссылается на него. То же для путей: таблица файлов, символ ссылается на файл.
- Причина: L — это 31 копия M, поэтому повторы имён там искусственные. В M интернирование
  сокращает байты имён в 1.28×, а в L — в 39.7×. Если интернирует только одна реализация,
  разница в размере образа и RAM будет артефактом корпуса, а не языка.
- Контрольная сумма это не проверяет; правило проверяется ревью кода. В отчёте основное
  сравнение памяти делается на M, а L служит стресс-тестом.

## Вывод
- `symidx build <dir> -o <img>` — stdout: `symbols=<N> files=<F>`.
- `symidx load <img>` — stdout: `symbols=<N> load_ms=<float>`.
- `symidx find <img> <prefix>` — все символы, у которых имя начинается с `<prefix>` (побайтово),
  по одному на строку: `name\tkind\tfile\tline\n`.
  Порядок: name (побайтово), затем file (побайтово), затем line (по числу).
  Пустой префикс выдаёт весь индекс — по нему считается контрольная сумма.
